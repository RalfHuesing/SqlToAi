## Intention

## Scope
comparison, performance measurement, optimization benchmark, index
suggestions and [DatabaseAnalysisServices](../../../src/SqlToAi/Database/DatabaseAnalysisServices.cs).
Carry context into nested validation, measurements, plans and connection calls.

## Exclusions

resolution, altered metrics, verdicts, permissions or query limits.

## Acceptance
each operation and benchmark sub-operation uses one endpoint
and policy identity; existing database fields are canonical. Verify SchemaOnly
rejection where required, rollback/cleanup, safe connection failures and parallel
same-name routing. Existing parameter isolation and raw-output limitations remain.

## Evidence
- `PerformanceMeasurementService.cs`, `QueryComparisonService.cs`, `OptimizationBenchmarkService.cs`, and `IndexSuggestionService.cs` route database parameters through `TargetResolver.Resolve(databaseName, _options.Value)` and execute via `PrimaryConnection.OpenTargetAsync(target)`.
- Nested benchmark sub-operations in `OptimizationBenchmarkService.cs` pass the canonical qualified database target to both comparison and performance sub-calls, ensuring consistent target identity across both stages.
- `PerformanceMeasurementResult.Database` and `OptimizationBenchmarkResult.Database` output canonical `$"{target.ServerAlias}/{target.DatabaseName}"` target names; IndexSuggestion Markdown headings render `# Missing Index Recommendations — {target.QualifiedName}`.
- Upfront target validation and security guards enforce static whitelists and access levels prior to SQL connections (`SQL-AI-0001` on invalid target, `SQL-AI-0104` on blocked target).
- SchemaOnly access level is rejected for execution-based analysis (`WriteOperationBlockedCode`), but permitted for DMV-based index suggestions.
- All analysis operations maintain transaction rollback and cancellation guarantees without connection leak.
- Unit and isolation suites updated and expanded with `AnalysisTargetIsolationTests.cs`, covering unqualified rejection, static whitelist guardrails, SchemaOnly differentiation, multi-server same-database routing, and canonical database reporting.
- Build: `dotnet build SqlToAi.slnx` clean with 0 warnings, 0 errors under `-warnaserror`.
