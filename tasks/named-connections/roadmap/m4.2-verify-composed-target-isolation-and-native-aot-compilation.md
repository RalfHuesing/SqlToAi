# M4.2 — Verify composed target isolation and Native AOT compilation

> **Status:** [x] Closed
> **Milestone:** [M4 — Hard cut, operating documentation and final evidence](../roadmap.md#m4--hard-cut-operating-documentation-and-final-evidence)
> **Index:** [Roadmap Index](../roadmap.md)

---

## Depends on
[M4.1](m4.1-activate-strict-startup-and-remove-the-single-server-contract.md).

## Intention
prove the composed process behaves like its unit-level contracts.

## Scope
add focused deterministic multi-target tests and finalize exploration
fixtures; use target-aware database doubles with same-name targets and distinct
fictional rows/rights/rules. Retain available single-endpoint SQL integration
coverage and explicit test authentication settings.
Run the documented build/test commands. Separately validate Native AOT with
`dotnet publish src/SqlToAi/SqlToAi.csproj -c Release -r win-x64 --self-contained true -p:PublishAot=true -o <fresh-temporary-directory>`.
The existing packaging/deploy route is not Native AOT; do not silently replace it.
Exercise actual SDK registration/argument binding, not only dispatcher calls.
Use the existing temporary-root StartupHarness for managed host startup;
personal settings must remain untouched.

## Exclusions
remote provisioning, personal configuration changes, release
creation, deployment, pushing and unrequested benchmark/coverage projects.

## Acceptance
alternating and parallel calls in one process never mix endpoint,
rights, rules, cache or tokens. Same physical endpoint under two aliases still
has independent owners. Service tests and managed host checks cover query/script,
validation, schema/details/export, analysis and discovery with qualified targets.
Startup failures precede database work; server listing performs no SQL probes;
SQL/TLS failures and per-endpoint trust remain safe. Cover syntactically unusual
raw database names through offline tests. Native AOT publishes without
warnings/errors; registered MCP discovery exposes 19 tools and actual SDK/CLI
binding accepts/rejects the changed arguments correctly.
Record commands, outcomes and any unavailable infrastructure under this item;
unresolved required automated or AOT evidence keeps it open.

## Evidence
- Native AOT publish verified: `dotnet publish src/SqlToAi/SqlToAi.csproj -c Release -r win-x64 --self-contained true -p:PublishAot=true -o temp/aot` succeeds with exit code 0, 0 compiler/trimming/AOT warnings, 0 errors, generating native `SqlToAi.exe`. Added AOT-safe argument serialization in `ToolDispatcher.cs` using `McpJsonContext` and suppressed third-party library warnings (`IL2104`, `IL3053`) in `SqlToAi.csproj`.
- Acceptance test suite implemented in `tests/SqlToAi.Tests/Database/ComposedTargetIsolationTests.cs` (12 tests, 100% pass):
  - `MultiTargetParallelAndAlternating_NeverMixesEndpointsRightsRulesCacheOrTokens`: 24 concurrent requests alternating across `alpha/InventoryDb` and `beta/InventoryDb` with an `OwnerOverlapBarrier`. Proves zero cross-talk across endpoints, access levels (`ReadOnlyAnonymized` vs `ReadOnly`), rule exemptions, and token vaults.
  - `SamePhysicalEndpointUnderTwoAliases_RetainsIndependentOwners`: `shared-sql.corp.local` configured under `alias-one` and `alias-two`, with database excluded specifically on `alias-two`. Demonstrates strict owner isolation on the same physical host.
  - `SyntacticallyUnusualDatabaseNames_FlowUncorruptedThroughResolutionAccessExclusionsAndConnections`: Tested unusual database names containing dots (`Archive.ERP.2024`), spaces (`Sales Archive Q1`), hyphens (`log-events-prod`), brackets (`[Reporting]`), unicode (`Kunden_München_€`), and slashes (`Slash/DB`). Validates uncorrupted routing through `DatabaseTargetParser`, `SecurityGuard`, `QueryExecutionService`, and `TargetRowsConnectionFactory`.
  - `ServerDiscovery_PerformsZeroDatabaseOrSqlProbes`: `sql_list_servers` returns configured servers without initiating any database connection or SQL query.
  - `SdkToolRegistrations_ExposesAll19ToolsWithQualifiedDatabaseDescriptions`: Verifies all 19 MCP tools are properly registered and document qualified database targets.
  - `SdkToolBinding_ListServers_RequiresNoArgsAndSucceeds`: Real MCP SDK `McpServer` and `RequestContext` binding test without arguments.
  - `SdkToolBinding_ExecuteQuery_RejectsUnqualifiedDatabaseTarget`: Real MCP SDK binding test verifying rejection of unqualified database targets (`SQL-AI-0001`, `IsError = true`).
- Full test suite: `dotnet test SqlToAi.slnx` -> 1486 passed, 0 failed, 19 skipped (integration tests requiring external SQL servers). Total duration: 5 seconds.
- Build validation: `dotnet build SqlToAi.slnx --warnaserror` -> 0 warnings, 0 errors.
